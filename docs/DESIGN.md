# WorkSlip UX direction

## Product personality
Capable, practical, calm, trustworthy. WorkSlip should feel like a well-made tool, not an accounting system designed for finance teams.

## Visual system
- Dark ink / charcoal foundation with warm paper-like content surfaces.
- Electric lime as the primary action accent.
- Muted slate for secondary information.
- Restrained amber/orange for overdue items and warnings.
- Strong type hierarchy, tabular numerals for money, generous spacing, subtle dividers.
- Avoid noisy gradients, excessive blur, generic dashboard templates, and tiny text.

## Interaction principles
1. One obvious primary action: create a job.
2. Show money in plain language: agreed price, costs, paid, still owed, estimated profit.
3. Distinguish estimates from actual expenses.
4. Never make destructive actions easy to trigger accidentally.
5. Keep common actions thumb-friendly on mobile.
6. Always explain an empty state and offer the next action.
7. Give immediate feedback after saving, payment entry, status change, and export.
8. Customer-facing receipts hide internal expenses and notes by default.

## Core mobile navigation
Home · Jobs · Money · Customers, plus a prominent New Job action.

## Dashboard hierarchy
- Date / greeting and New Job CTA
- Receivables or money-still-owed highlight
- Active jobs, received this month, outstanding, estimated profit
- Job status pipeline
- Needs attention
- Recent jobs

## Accessibility
Readable contrast, sensible touch targets, keyboard focus states, form labels, non-color status cues, and reduced-motion support.

## Copy style
Short, plain language. Prefer "Still owed" over "Accounts receivable", "Costs" over "Operating expenditures", and "Record payment" over "Log transaction".
